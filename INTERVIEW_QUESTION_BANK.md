## 3. Backend engineering umum

### 1. Jelaskan alur request dari frontend sampai database

Frontend mengirim HTTP request ke endpoint. Router menentukan handler yang sesuai, middleware menjalankan authentication atau validasi umum, lalu handler membaca input. Business logic idealnya dijalankan di service/use-case dan akses database dilakukan repository. Hasilnya dikembalikan sebagai response dengan status dan format yang konsisten.

### 2. Apa perbedaan handler, service, dan repository?

- Handler menangani detail HTTP seperti request, response, parameter, dan status code.
- Service/use-case menangani business rule dan orkestrasi proses.
- Repository menangani penyimpanan dan pengambilan data.

### 3. Mengapa menggunakan repository pattern?

Untuk memisahkan business logic dari detail database, mempermudah testing, dan menjaga query tetap terorganisasi. Kekurangannya, abstraksi berlebihan bisa menambah boilerplate pada aplikasi kecil.

### 4. Manfaat dan kelemahan layered architecture?

Manfaatnya adalah pemisahan tanggung jawab dan kemudahan testing. Kelemahannya, terlalu banyak layer bisa membuat perubahan sederhana menjadi panjang. Jumlah layer harus mengikuti kompleksitas aplikasi.

### 5. Bagaimana merancang REST API yang konsisten?

Gunakan penamaan resource, HTTP method, status code, format error, pagination, dan validasi yang konsisten. Dokumentasikan contract dan jangan membocorkan detail internal melalui error response.

### 6. Perbedaan POST, PUT, PATCH, dan DELETE?

- `POST`: membuat resource atau menjalankan aksi yang tidak idempotent.
- `PUT`: mengganti representasi resource secara utuh dan biasanya idempotent.
- `PATCH`: memperbarui sebagian field.
- `DELETE`: menghapus atau menonaktifkan resource.

### 7. Perbedaan authentication dan authorization?

Authentication menjawab siapa pengguna. Authorization menentukan apa yang boleh dilakukan pengguna tersebut.

### 8. Bagaimana JWT bekerja?

Server menerbitkan token bertanda tangan yang berisi claim. Client mengirim token pada request berikutnya. Server memverifikasi signature, expiry, issuer, dan claim sebelum mempercayainya. JWT ditandatangani, bukan otomatis terenkripsi.

### 9. Risiko menyimpan JWT di localStorage?

JavaScript dapat mengaksesnya, sehingga token bisa dicuri jika terjadi XSS. Untuk token jangka panjang, cookie `HttpOnly`, `Secure`, dan konfigurasi `SameSite` biasanya lebih aman.

### 10. Mengapa refresh token disimpan dalam cookie HttpOnly?

Supaya JavaScript frontend tidak dapat membacanya secara langsung. Ini mengurangi risiko pencurian token melalui XSS, meskipun perlindungan CSRF dan konfigurasi cookie tetap harus diperhatikan.

### 11. Apa itu refresh-token rotation?

Setiap refresh menghasilkan refresh token baru dan token lama dicabut. Jika token lama digunakan kembali, sistem dapat mendeteksi potensi penyalahgunaan.

### 12. Bagaimana mencabut session pengguna?

Simpan session atau hash refresh token di server. Saat logout atau revocation, tandai session tidak aktif. Request berikutnya harus memeriksa bahwa session terkait token masih valid.

### 13. Apa itu RBAC?

Role-Based Access Control memberikan izin berdasarkan role, misalnya admin, cashier, dan viewer. Pemeriksaan harus dilakukan di backend; menyembunyikan tombol di frontend saja tidak cukup.

### 14. Bagaimana mencegah akses endpoint di luar role?

Gunakan middleware/policy backend pada setiap route sensitif, uji matriks akses, dan jangan mempercayai role yang dikirim client.

### 15. Apa itu idempotency?

Request yang sama dapat diulang tanpa menghasilkan efek tambahan. Pada checkout, idempotency key mencegah transaksi ganda ketika client mengulang request akibat timeout jaringan.

### 16. Mengapa pembayaran memerlukan idempotency key?

Karena client atau payment provider dapat mengirim request/callback ulang. Tanpa idempotency, satu pembayaran dapat membuat transaksi atau pengurangan stok lebih dari sekali.

### 17. Bagaimana menangani race condition?

Gunakan database transaction, conditional update, locking ketika diperlukan, unique constraint, dan idempotency. Pilihan mekanisme bergantung pada resource serta tingkat contention.

### 18. Apa fungsi database transaction?

Menjaga beberapa operasi sebagai satu kesatuan: semuanya berhasil atau semuanya dibatalkan. Ini penting saat membuat transaksi, detail transaksi, mutasi stok, dan pembayaran.

### 19. Apa itu atomic stock update?

Pemeriksaan ketersediaan dan pengurangan stok dilakukan dalam operasi/transaction yang aman, sehingga dua request tidak dapat sama-sama menggunakan stok terakhir berdasarkan pembacaan lama.

### 20. Bagaimana mencegah stok negatif?

Lakukan validasi di dalam transaction, gunakan conditional update seperti `stock >= quantity`, periksa affected rows, dan tambahkan constraint database jika sesuai.

### 21. Apa itu database locking?

Lock membatasi operasi concurrent terhadap data tertentu. Row-level lock dapat digunakan saat transaksi perlu membaca lalu memperbarui baris yang sama secara konsisten.

### 22. Bagaimana menangani kegagalan di tengah transaksi?

Kembalikan error dan lakukan rollback. Jangan mengirim response sukses sebelum commit berhasil.

### 23. Perbedaan soft delete dan hard delete?

Soft delete menandai data terhapus tetapi tetap menyimpannya. Hard delete benar-benar menghapus record. Soft delete membantu audit dan pemulihan, tetapi query serta unique constraint menjadi lebih kompleks.

### 24. Kapan soft delete tidak cocok?

Untuk data sensitif yang wajib dihapus, data sementara yang besar, atau ketika mempertahankan record tidak memiliki nilai bisnis dan justru meningkatkan risiko.

### 25. Bagaimana merancang audit log?

Catat actor, action, resource, waktu, hasil, dan metadata perubahan yang relevan. Hindari menyimpan password, token, atau data sensitif secara mentah.

### 26. Bagaimana melakukan pagination?

Validasi `page` dan `per_page`, berikan batas maksimal, gunakan query `LIMIT/OFFSET` atau cursor, dan sertakan metadata total jika memang dibutuhkan.

### 27. Offset vs cursor pagination?

Offset mudah digunakan tetapi dapat melambat dan berubah hasilnya pada data yang aktif. Cursor lebih stabil dan efisien untuk data besar, tetapi implementasi dan navigasinya lebih kompleks.

### 28. Bagaimana mencegah SQL injection?

Gunakan parameterized query/prepared statement, bukan menyusun SQL dari input. Untuk dynamic sorting, gunakan allowlist nama kolom dan arah sorting.

### 29. Apa itu N+1 query?

Satu query mengambil daftar, lalu satu query tambahan dijalankan untuk setiap item. Solusinya dapat berupa JOIN, batch query, eager loading, atau perubahan bentuk data.

### 30. Bagaimana mencari penyebab endpoint lambat?

Ukur dulu: waktu total, query database, call eksternal, serialisasi, dan ukuran response. Gunakan log/trace, `EXPLAIN ANALYZE`, serta benchmark sebelum dan sesudah perubahan.

**Poin jawaban ringkas:**

- Go dipilih karena sederhana, typed, cepat dikompilasi, memiliki standard library yang baik, dan cocok untuk service/backend.
- Error di Go dikembalikan sebagai value dan diperiksa secara eksplisit; tambahkan context saat membungkus error.
- Interface mendeskripsikan behavior dan dipenuhi secara implisit. Buat interface kecil di sisi consumer.
- Pointer digunakan ketika perlu memodifikasi nilai yang sama, menghindari copy besar, atau membedakan nilai kosong tertentu. Jangan memakai pointer tanpa alasan.
- Array memiliki panjang tetap sebagai bagian dari tipenya; slice adalah view dinamis di atas backing array.
- Goroutine adalah unit concurrency ringan. Channel membantu komunikasi/sinkronisasi, tetapi mutex sering lebih tepat untuk shared state sederhana.
- `context.Context` membawa cancellation, deadline, dan request-scoped values. Teruskan sebagai argumen pertama dan jangan menyimpannya di struct tanpa alasan kuat.
- Middleware membungkus `http.Handler` untuk authentication, logging, recovery, dan concern lintas endpoint.
- `net/http` pada Go POS digunakan untuk mempelajari fondasi standard library dan kontrol arsitektur. Gin pada COSMO membantu routing dan kebutuhan tim yang sudah ditentukan.
- Data race dicegah dengan menghindari shared mutable state, memakai mutex/channel secara tepat, dan menjalankan race detector.
- Unit test mengisolasi logic; integration test memeriksa kerja sama dengan komponen nyata seperti PostgreSQL.
- Dependency injection dapat dilakukan lewat constructor yang menerima interface/dependency.
- Hindari circular dependency dengan arah dependency yang jelas dan package berdasarkan domain/tanggung jawab.
- Graceful shutdown menghentikan penerimaan request baru, menunggu request aktif, lalu menutup resource dengan timeout.
- `defer` menjadwalkan fungsi saat scope berakhir, umum untuk cleanup dan rollback guard.
- Secret dibaca dari environment/secret manager, tidak di-commit, divalidasi saat startup, dan tidak dicetak ke log.

## 10. Database dan SQL

1. Apa perbedaan PostgreSQL dan MySQL?
2. Apa itu primary key, foreign key, dan unique constraint?
3. Apa fungsi index?
4. Kapan index memperlambat sistem?
5. Jelaskan jenis JOIN.
6. Apa perbedaan `WHERE` dan `HAVING`?
7. Bagaimana mendeteksi query lambat?
8. Apa itu isolation level?
9. Apa itu deadlock?
10. Bagaimana mencegah lost update?
11. Bagaimana membuat migration aman?
12. Bagaimana mengubah schema pada sistem aktif?
13. Bagaimana menjaga integritas stok dan transaksi?
14. Bagaimana mendesain tabel session dan refresh token?
15. Mengapa refresh token disimpan dalam bentuk hash?

**Poin jawaban ringkas:**

- PostgreSQL kuat pada fitur SQL, extensibility, dan tipe data; MySQL juga matang dan banyak digunakan. Pilihan harus mempertimbangkan kebutuhan dan kemampuan tim.
- Primary key mengidentifikasi record, foreign key menjaga relasi, unique constraint mencegah duplikasi nilai tertentu.
- Index mempercepat read tetapi menambah storage dan biaya insert/update/delete.
- `INNER JOIN` mengambil pasangan yang cocok; `LEFT JOIN` mempertahankan semua baris kiri; `RIGHT/FULL` mengikuti sisi yang dipertahankan.
- `WHERE` memfilter baris sebelum agregasi; `HAVING` memfilter hasil grup.
- Gunakan slow query log, metrics, dan `EXPLAIN ANALYZE`; jangan menambah index berdasarkan tebakan.
- Isolation level menentukan seberapa jauh transaksi melihat perubahan concurrent.
- Deadlock terjadi ketika transaksi saling menunggu lock. Database biasanya membatalkan salah satu; kurangi risiko dengan urutan lock konsisten dan transaksi singkat.
- Lost update dicegah dengan locking, conditional update, version column, atau isolation yang sesuai.
- Migration aman bersifat kecil, backward-compatible bila memungkinkan, diuji pada data representatif, dan memiliki rencana rollback.
- Integritas stok dijaga melalui database transaction, constraint, locking/conditional update, dan audit movement.
- Session menyimpan user, expiry, status/revocation, dan hash refresh token. Token mentah hanya dimiliki client.
- Hash refresh token membatasi dampak jika database bocor, seperti penyimpanan password hash.
